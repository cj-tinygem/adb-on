## 为什么选择 adb-on？

做好了 Android 应用，却在连接自己手机的那一刻卡住了？

查找 `adb` 的安装位置、复制命令、重新输入变化的端口，这些都不是开发应用的核心工作。adb-on 只把连接所需的事项放进一个小窗口。

- **USB 自动检测：** 区分已连接、等待手机授权、无响应三种状态。
- **无线按引导操作：** 选择发现的地址，输入手机上的 6 位配对码。若无法自动发现，可以手动输入地址。
- **首次连接逐步引导：** 从开发者选项到手机上的允许按钮，逐步说明。
- **与现有工具共存：** 使用默认 ADB 服务器。不会强制终止现有服务器，也不会删除认证密钥。
- **只保留必要功能：** 不含云服务器、屏幕镜像、文件管理器，专注于连接。

|macOS Apple Silicon|`adb-on.app`|尚未发布。构建路径已准备，未在实际 Mac 上验证。|
|macOS Intel|`adb-on.app`|尚未发布。构建路径已准备，未在实际 Mac 上验证。|

- 没有安装程序。解压后，将单个 `adb-on.exe` 放到任意文件夹中运行即可。压缩包中的许可证文件不是运行应用所必需的。

- 应用语言默认跟随电脑语言，可在工具设置中切换为 English、简体中文、日本語、Español、한국어、Deutsch、Français。

每次发布都会一并提供可执行文件的 **SHA-256 校验和**与验证范围。请查看发布说明，以免混淆开发测试版与正式支持版本。

## 通过 USB 首次连接

### 1. 打开 adb-on

若提示未找到 ADB，请点击**准备首次连接**。确认并同意 Google SDK 条款后，应用会下载并准备官方文件。

若已安装 Android Studio，通常会跳过此步骤。若工具安装在其他位置，可以在**工具设置 → 选择已有的 ADB 文件**中选择 `adb.exe` 或 `adb`。

### 2. 在手机上打开开发者选项

|手机|菜单路径|
|---|---|
|Galaxy|设置 → 关于手机 → 软件信息 → 连续点按**版本号** 7 次|
|Pixel 等|设置 → 关于手机 → 连续点按**版本号** 7 次|

若要求输入锁屏密码，请**直接在手机上**输入。菜单名称可能因机型和 Android 版本而异。

### 3. 开启 USB 调试

开启手机设置中的**开发者选项 → USB 调试**。出于 Android 安全要求，此步骤必须在手机上直接完成。

### 4. 用数据线连接并允许

解锁手机，点按**是否允许 USB 调试？ → 允许**。若是本人的 PC，选择“一律允许”可以让下次连接更方便。

当 adb-on 显示为**已连接**后，在这台 PC 的开发工具中选择手机即可。

> 仅支持充电的线缆无法用于 ADB 连接。对于未在手机上允许的设备，不会从 PC 端强制批准。

## 不使用数据线连接

使用 Android 11 及以上版本支持的无线调试。

### 1. 连接到同一 Wi-Fi

PC 与手机必须处于可以相互通信的网络。公司、学校、访客 Wi-Fi 可能会阻止设备间通信。

### 2. 在手机上打开配对界面

选择**设置 → 开发者选项 → 无线调试 → 使用配对码配对设备**。保持此界面打开。

### 3. 在 adb-on 中点击无线连接

点击发现的配对地址，输入手机上显示的 **6 位数字**，然后点击**配对**。若只发现一个地址，会自动填入。若显示多台手机，请与自己手机屏幕上的地址核对。

自动发现会持续一小段时间。即使未能发现，也可以直接输入手机上显示的 **IP 地址:端口**。

### 4. 确认连接状态

配对是将 PC 注册为受信任设备的过程，与完成连接不同。

若未能连接，请在手机上返回上一界面，将**无线调试首页的 IP 地址和端口**输入到 adb-on 的连接栏中，然后点击**连接**。

|地址|在哪里？|填到哪里？|
|---|---|---|
|配对地址|“使用配对码配对设备”弹窗|① 配对地址栏|
|连接地址|无线调试首页|② 连接地址栏|

**两个端口不同。** 例如，配对可能是 `192.168.1.5:37123`，而连接可能是 `192.168.1.5:39511`。请勿复制示例，使用手机上的实际值。

## 下次重新连接时

- **USB：** 若是此前已信任的 PC，插入数据线后确认状态即可。若需要再次授权，请在手机上允许。
- **无线：** 在同一网络中开启无线调试，且 ADB 发现设备后会重新连接。若无法自动连接，请使用手机上的**当前连接地址**。
- **重启或更换 Wi-Fi 后：** 无线调试可能被关闭，IP 与端口也可能变化。adb-on 不会保存过期地址并持续尝试。
- **退出应用：** 关闭窗口后 adb-on 即退出。其他开发工具使用的 ADB 服务器与连接会保持。没有隐藏的 adb-on 常驻服务。
- **断开无线连接：** 点击对应设备的断开按钮。由于 ADB 可能自动重连，若要确保断开，请在手机上关闭无线调试。

## 遇到问题时快速查找

|看到的情况|先做的事|
|---|---|
|手机上等待授权|解锁手机，查看允许 USB 调试的弹窗|
|已插入 USB 但看不到手机|依次检查数据线、其他端口、USB 调试|
|在 Windows 上仍然看不到|查看[制造商 USB 驱动程序说明](https://developer.android.com/studio/run/oem-usb)|
|搜索不到无线设备|保持配对弹窗打开，或直接输入地址|
|配对码被拒绝|在手机上打开新的配对弹窗，输入新的配对码和地址|
|已配对但未连接|使用无线调试首页的**连接地址**进行连接|
|在公司 Wi-Fi 上无法使用|即使在同一网络中也可能被阻止通信。请使用 USB 连接|
|提示 ADB 服务器版本不同|选择与正在使用的开发工具相同的 ADB 文件|
|开发工具中找不到手机|确认是否使用同一 PC 环境中的默认 ADB 服务器。WSL 是独立环境|
|ADB 下载失败|连接互联网后重新准备，或选择已有的 ADB 文件|

在应用内的**USB 连接指南**中也可以逐步查看同样的说明。仅凭空的设备列表，不会断定原因是驱动程序、数据线还是手机设置。

## 自动处理哪些事项？

|PC 端处理的事项|需要在手机上直接完成的事项|
|---|---|
|查找现有 ADB、确认连接状态|开启开发者选项、USB/无线调试|
|同意后下载官方 ADB、校验文件|首次信任 PC 的授权|
|发现无线地址、配对命令、连接请求|打开配对界面、确认 6 位配对码|
|根据状态提示下一步操作|解决公司管理策略等手机权限问题|

不提供屏幕镜像、文件管理、应用构建、Root、驱动程序自动安装。

## 小而快的标准

不会仅凭可执行文件体积小就宣称性能。发布前会测量以下项目。

- 从启动到窗口显示的时间。
- 空闲 CPU 与内存。现有的共享 ADB 服务器单独区分。
- 可执行文件与首次下载的大小。
- 手机连接与断开时的状态刷新，以及操作过程中的界面响应。

GUI 由 **Rust + Slint** 构成，不启动系统 WebView。状态变化使用 ADB 的通知，无线发现查询仅在用户打开无线连接时于限定时间内执行。

Windows 开发构建实测（未连接手机，2026-09-11）：

|项目|结果|
|---|---|
|可执行文件|约 12.0MiB|
|空闲内存|工作集约 126MiB，私有内存约 59MiB（GPU 绘制；工作集大部分是显卡驱动内存）|
|三次重新启动的窗口显示|0.47~0.57 秒|
|共享 ADB 服务器|单独约 4.7MiB，保留现有进程|

每次运行中，30 秒空闲消耗 0.13~0.36 秒 CPU 时间（约为单核的 0.4~1.2%）。从此版本起窗口由 GPU 绘制；常见问题中的软件绘制回退约占 30MiB，但滚动不够流畅。此前首个构建的首次启动为 1.43 秒，不保证冷启动或其他 PC 的性能。设备连接过程中的负载与 macOS 性能尚未验证。

## 我的 PC 上会留下什么？

- ADB 位置设置（`settings.json`），以及在选择了应用内准备时的官方 ADB 副本。两者都只保存在下面的文件夹中。
  - Windows：`%LOCALAPPDATA%\tinygem\adb-on\data\`
  - macOS：`~/Library/Application Support/ai.tinygem.adb-on/`
- 由 ADB 自身管理的 PC 认证密钥与服务器。adb-on 不会删除或替换现有密钥。

配对码不会保存到设置或使用日志中。没有远程存储服务器。自动准备时会访问 Google 下载服务器，说明链接会在默认浏览器中打开。

若不再使用应用，请选择**工具设置 → 删除 adb-on 数据**，然后关闭窗口并删除可执行文件。若已经删除了可执行文件，请自行删除上述文件夹。若此处准备的 ADB 正在作为服务器运行，删除时会将其停止；其他工具的 ADB 与 ADB 认证密钥不会被触及。仅删除可执行文件不会移除此文件夹。

## 常见问题

### 需要安装吗？

不需要。将单个 `adb-on.exe` 放到任意文件夹中运行即可。设置与准备好的 ADB 保存在上述用户数据文件夹中，可以在工具设置中删除。

### 是开源的吗？

是的。源代码以 MIT 许可证公开。第三方组件遵循各自的许可证。

### 不了解 ADB 也可以吗？

基本连接不需要命令。需要在手机上完成的授权与设置会在界面上提示。

### 没有 Android Studio 也能开发应用吗？

adb-on 是连接工具。它不能替代构建应用所需的 SDK 与构建工具。

### 在 Windows 上连接后，WSL 中也能用吗？

不会自动传递。Windows 与 WSL 可能是各自独立的开发环境。

### macOS 上同时支持 Intel 与 Apple Silicon 吗？

两种架构的构建路径已准备，但 macOS 构建尚未发布，也未在实际 Mac 上验证。即使发布，也不会带有 Apple Developer ID 签名，因此首次打开需要右键点击 → 打开，仅需一次。

### 需要在手机上安装额外的应用吗？

adb-on 的连接不需要在手机上安装额外应用。使用的是 Android 的调试功能。
