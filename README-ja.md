## なぜ adb-on なのですか？

Android アプリを作ったのに、自分のスマートフォンに接続する段階で止まってしまいましたか？

`adb` のインストール場所を探し、コマンドをコピーし、変わったポートを再入力する作業は、アプリ作りの本質ではありません。adb-on は接続に必要な作業だけを小さなウィンドウにまとめます。

- **USB は自動確認:** 接続済み・スマートフォンの承認待ち・応答なしを区別します。
- **無線は案内どおりに:** 検出したアドレスを選択し、スマートフォンの 6 桁コードを入力します。自動検出できない場合は、アドレスを直接入力できます。
- **初回は一段階ずつ:** 開発者向けオプションからスマートフォンの許可ボタンまで案内します。
- **既存のツールと共存:** 既定の ADB サーバーを使用します。既存のサーバーを無条件に終了したり、認証キーを削除したりしません。
- **必要な機能だけ:** クラウドサーバー、ミラーリング、ファイルマネージャーなしで接続に集中します。

## ダウンロードと対応状況

公式配布場所: [adb-on ダウンロードとリリース](https://github.com/cj-tinygem/adb-on/releases)

|プラットフォーム|提供形態|現在の状態|
|---|---|---|
|Windows x64|`adb-on.exe`|利用可能。実機との USB・Wi-Fi 接続を検証済み。コードによるペアリングは実機検証待ち。|
|macOS Apple Silicon|`adb-on.app`|未公開。ビルド経路は準備済み、実際の Mac では未検証。|
|macOS Intel|`adb-on.app`|未公開。ビルド経路は準備済み、実際の Mac では未検証。|

- インストーラーはありません。zip を展開し、`adb-on.exe` 1 つを任意のフォルダーに置いて実行してください。zip 内のライセンスファイルはアプリの実行には必要ありません。
- Windows アプリは WebView2・Node.js・Java を必要としません。
- アプリの言語は最初は PC の言語に従います。ツール設定で English・简体中文・日本語・Español・한국어・Deutsch・Français から選べます。
- ADB がすでにある場合は再利用します。ない場合は、アプリ内で規約に同意した後に Google 公式ツールを準備します。初回の準備にはインターネット接続が必要です。
- 現在の開発ビルドは、公的なコード署名・公証を済ませた配布物ではありません。OS の警告を自動的に解除したり、セキュリティ設定を変更したりしません。
- macOS の目標最小バージョンは 12 です。実際の互換範囲はネイティブ検証後に確定します。
- Linux・Windows ARM のネイティブ対応は現在提供していません。

リリースごとに実行ファイルの **SHA-256 チェックサム**と検証範囲を併せて提供します。開発試験版と正式対応版を混同しないよう、リリースの説明を確認してください。

## USB で初めて接続する

### 1. adb-on を開きます

ADB がないという案内が表示されたら、**初回接続の準備**を押します。Google SDK の規約を確認して同意すると、アプリが公式ファイルをダウンロードして準備します。

Android Studio がすでにインストールされている場合は、通常この手順を省略できます。ツールを別の場所にインストールしている場合は、**ツール設定 → 既存の ADB ファイルを選択**で `adb.exe` または `adb` を選択できます。

### 2. スマートフォンで開発者向けオプションを開きます

|スマートフォン|たどるメニュー|
|---|---|
|Galaxy|設定 → 端末情報 → ソフトウェア情報 → **ビルド番号**を 7 回タップ|
|Pixel など|設定 → デバイス情報 → **ビルド番号**を 7 回タップ|

ロック解除のパスワードを求められたら、**スマートフォンで直接**入力してください。機種・Android のバージョンによってメニュー名が異なる場合があります。

### 3. USB デバッグをオンにします

スマートフォンの設定で **開発者向けオプション → USB デバッグ**をオンにします。この操作は Android のセキュリティ上、スマートフォンで直接行う必要があります。

### 4. データケーブルで接続して許可します

スマートフォンのロックを解除し、**USB デバッグを許可しますか？ → 許可**を押します。自分の PC であれば「常に許可」を選択すると、次回以降の接続が楽になります。

adb-on が **接続されました**に変わったら、この PC の開発ツールでスマートフォンを選択してください。

> 充電専用のケーブルは ADB 接続に使用できません。許可していないスマートフォンを PC 側から強制的に承認することはありません。

## ケーブルなしで接続する

Android 11 以降で対応しているワイヤレスデバッグを使用します。

### 1. 同じ Wi-Fi に接続します

PC とスマートフォンが互いに通信できるネットワークである必要があります。会社・学校・ゲスト用の Wi-Fi は、端末間の通信を遮断している場合があります。

### 2. スマートフォンでペア設定画面を開きます

**設定 → 開発者向けオプション → ワイヤレスデバッグ → ペア設定コードによるデバイスのペア設定**を選択します。この画面を開いたままにします。

### 3. adb-on で無線接続を押します

検出されたペア設定アドレスを押し、スマートフォンに表示されている **6 桁の数字**を入力して **ペア設定する**を押します。アドレスが 1 つだけ検出された場合は自動的に入力されます。複数のスマートフォンが表示される場合は、自分のスマートフォン画面のアドレスと照合してください。

自動検出はしばらく継続します。見つからない場合でも、スマートフォンに表示されている **IP アドレス:ポート**を直接入力できます。

### 4. 接続状態を確認します

ペア設定は PC を信頼するよう登録する手順であり、接続完了とは異なります。

接続できない場合は、スマートフォンで 1 画面戻り、**ワイヤレスデバッグの最初の画面にある IP アドレスとポート**を adb-on の接続欄に入力して **接続する**を押します。

|アドレス|どこにありますか？|どこに入力しますか？|
|---|---|---|
|ペア設定アドレス|「ペア設定コードによるデバイスのペア設定」のポップアップ|① ペア設定アドレス欄|
|接続アドレス|ワイヤレスデバッグの最初の画面|② 接続アドレス欄|

**2 つのポートは異なります。** 例えば、ペア設定は `192.168.1.5:37123`、接続は `192.168.1.5:39511` のようになる場合があります。例をコピーせず、スマートフォンに表示された値を使用してください。

## 次回再接続するとき

- **USB:** 以前に信頼した PC であれば、ケーブルを挿して状態を確認します。再度承認が必要な場合は、スマートフォンで許可してください。
- **無線:** 同じネットワークでワイヤレスデバッグがオンになっており、ADB がデバイスを検出すれば再接続されます。自動接続できない場合は、スマートフォンの **現在の接続アドレス**を使用してください。
- **再起動・Wi-Fi 変更後:** ワイヤレスデバッグがオフになったり、IP・ポートが変わったりする場合があります。adb-on は古いアドレスを保存して試行し続けることはありません。
- **アプリの終了:** ウィンドウを閉じると adb-on は終了します。他の開発ツールが使用している ADB サーバーと接続は維持します。隠れた adb-on の常駐サービスはありません。
- **無線接続の解除:** 該当デバイスの解除ボタンを押します。ADB が自動的に再接続する場合があるため、確実に切断しておきたい場合はスマートフォンでワイヤレスデバッグをオフにしてください。

## 困ったときにすぐ探す

|表示される状況|まず行うこと|
|---|---|
|スマートフォンで承認待ち|スマートフォンのロックを解除し、USB デバッグの許可ポップアップを確認|
|USB を挿したのにスマートフォンが表示されない|データケーブル・別のポート・USB デバッグの順に確認|
|それでも Windows で表示されない|[メーカー製 USB ドライバの案内](https://developer.android.com/studio/run/oem-usb)を確認|
|無線デバイスが検出されない|ペア設定ポップアップを開いたままにするか、アドレスを直接入力|
|ペア設定コードが拒否される|スマートフォンで新しいペア設定ポップアップを開き、新しいコード・アドレスを入力|
|ペア設定できたが接続できない|ワイヤレスデバッグの最初の画面にある **接続アドレス**で接続|
|会社の Wi-Fi でつながらない|同じネットワークでも通信が遮断されている場合がある。USB 接続を使用|
|別の ADB サーバーバージョンの案内|使用中の開発ツールと同じ ADB ファイルを選択|
|開発ツールでスマートフォンが見つからない|同じ PC 環境の既定の ADB サーバーを使用しているか確認。WSL は別環境|
|ADB のダウンロード失敗|インターネットに接続してから再度準備するか、既存の ADB ファイルを選択|

アプリ内の **USB 接続ガイド**でも、同じ案内を一段階ずつ確認できます。空のデバイス一覧だけで、ドライバ・ケーブル・スマートフォンの設定のどれが原因かを断定することはありません。

## 何を自動で行いますか？

|PC 側で処理すること|スマートフォンで直接行う必要があること|
|---|---|
|既存の ADB の検索・接続状態の確認|開発者向けオプション・USB/ワイヤレスデバッグをオンにする|
|同意後の公式 ADB のダウンロード・ファイル検証|初回の PC 信頼の承認|
|無線アドレスの検出・ペア設定コマンド・接続要求|ペア設定画面を開く・6 桁コードの確認|
|状態に応じた次の操作の案内|会社の管理ポリシーなどスマートフォン側の権限問題の解決|

画面ミラーリング・ファイル管理・アプリのビルド・root 化・ドライバの自動インストールは提供しません。

## 小さく速いという基準

実行ファイルが小さいことだけを根拠に性能を主張することはしません。配布前に以下の項目を測定します。

- 起動からウィンドウが表示されるまでの時間。
- アイドル時の CPU とメモリ。既存の共有 ADB サーバーは別に区分します。
- 実行ファイルと初回ダウンロードの容量。
- スマートフォンの接続・取り外し時の状態更新と、操作中の画面応答。

GUI は **Rust + Slint** で構成し、システムの WebView を起動しません。状態変化は ADB の通知を使用し、無線検出の照会はユーザーが無線接続を開いたときに限られた時間だけ実行します。

Windows 開発ビルドの実測値(接続されたスマートフォンなし、2026-09-11):

|項目|結果|
|---|---|
|実行ファイル|約 12.0MiB|
|アイドル時メモリ|ワーキングセット約 126MiB、プライベート約 59MiB (GPU 描画。ワーキングセットの大半はグラフィックドライバーのメモリ)|
|3 回再起動したときのウィンドウ表示|0.47~0.57 秒|
|共有 ADB サーバー|別途約 4.7MiB、既存プロセスを維持|

各実行において、30 秒間のアイドルで 0.13~0.36 秒の CPU 時間を使用しました (1 コアの約 0.4~1.2%)。このビルドからウィンドウは GPU で描画します。FAQ のソフトウェア描画フォールバックは約 30MiB ですが、スクロールは滑らかさに欠けます。先行する最初のビルドの初回起動は 1.43 秒であり、コールドブートや他の PC の性能を保証するものではありません。デバイス接続中の負荷と macOS の性能はまだ検証していません。

## 自分の PC に何が残りますか？

- ADB の場所の設定(`settings.json`)と、アプリ内での準備を選択した場合は公式 ADB のコピー。どちらも以下のフォルダーにのみ保存されます。
  - Windows: `%LOCALAPPDATA%\tinygem\adb-on\data\`
  - macOS: `~/Library/Application Support/ai.tinygem.adb-on/`
- ADB 自体が管理する PC の認証キーとサーバー。既存のキーを adb-on が削除・置換することはありません。

ペア設定コードは設定・使用ログに保存しません。リモート保存サーバーはありません。自動準備時に Google のダウンロードサーバーに接続し、案内リンクは既定のブラウザで開きます。

アプリの使用をやめる場合は、**ツール設定 → adb-on のデータを削除**を選択してから、ウィンドウを閉じて実行ファイルを削除してください。実行ファイルをすでに削除している場合は、上記のフォルダーをご自身で削除してください。ここで準備した ADB がサーバーとして実行中の場合は、削除時に停止します。他のツールの ADB と ADB の認証キーには手を加えません。実行ファイルを削除しただけでは、このフォルダーは削除されません。

## よくある質問

### インストールは必要ですか？

いいえ。`adb-on.exe` 1 つを任意のフォルダーに置いて実行してください。設定と準備した ADB は上記のユーザーデータフォルダーに保存され、ツール設定から削除できます。

### オープンソースですか？

はい。ソースコードは MIT ライセンスで公開しています。サードパーティのコンポーネントはそれぞれのライセンスに従います。

### ADB を知らなくても大丈夫ですか？

基本的な接続にコマンドは必要ありません。スマートフォン側で必要な承認と設定は画面で案内します。

### Android Studio なしでアプリを開発できますか？

adb-on は接続ツールです。アプリのビルドに必要な SDK・ビルドツールの代わりにはなりません。

### Windows で接続すれば WSL でも使えますか？

自動的には引き継がれません。Windows と WSL は別の開発環境である場合があります。

### macOS では Intel と Apple Silicon の両方に対応していますか？

両アーキテクチャ向けのビルド経路は準備していますが、macOS ビルドはまだ公開しておらず、実際の Mac でも未検証です。公開しても Apple Developer ID の署名はないため、初回起動時に一度だけ右クリック → 開く が必要です。

### スマートフォンに別のアプリをインストールしますか？

adb-on の接続のためにスマートフォンへ別のアプリをインストールすることはありません。Android のデバッグ機能を使用します。

## 問題の報告と利用条件

[問題の報告](https://github.com/cj-tinygem/adb-on/issues)で次の情報をお知らせください。

- PC の OS、スマートフォンの機種と Android のバージョン。
