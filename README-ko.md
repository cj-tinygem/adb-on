## 왜 adb-on인가요?

Android 앱을 만들었는데, 내 폰에 연결하는 순간 막혔나요?

`adb` 설치 위치를 찾고, 명령어를 복사하고, 바뀐 포트를 다시 입력하는 일은 앱 만들기의 핵심이 아닙니다. adb-on은 연결에 필요한 일만 작은 창에 담습니다.

- **USB는 자동 확인:** 연결됨·휴대폰 승인 대기·응답 없음을 구분합니다.
- **무선은 안내대로:** 발견한 주소를 선택하고 휴대폰의 6자리 코드를 입력합니다. 자동 발견이 안 되면 주소를 직접 입력할 수 있습니다.
- **처음에는 한 단계씩:** 개발자 옵션부터 폰의 허용 버튼까지 안내합니다.
- **기존 도구와 함께:** 기본 ADB 서버를 사용합니다. 기존 서버를 무조건 종료하거나 인증키를 지우지 않습니다.
- **필요한 기능만:** 클라우드 서버, 미러링, 파일 관리자 없이 연결에 집중합니다.

## 다운로드와 지원 상태

공식 배포 위치: [adb-on 다운로드와 릴리스](https://github.com/cj-tinygem/adb-on/releases)

|플랫폼|제공 형태|현재 상태|
|---|---|---|
|Windows x64|`adb-on.exe`|사용 가능. 실제 휴대폰과 USB·Wi-Fi 연결 검증 완료. 코드 페어링은 실폰 검증 대기.|
|macOS Apple Silicon|`adb-on.app`|미공개. 빌드 경로는 준비됐고 실제 Mac 검증은 안 됨.|
|macOS Intel|`adb-on.app`|미공개. 빌드 경로는 준비됐고 실제 Mac 검증은 안 됨.|

- 설치 프로그램이 없습니다. 압축을 풀고 `adb-on.exe` 하나를 원하는 폴더에 두고 실행하면 됩니다. 함께 들어 있는 라이선스 파일은 실행에 필요하지 않습니다.
- Windows 앱은 WebView2·Node.js·Java를 요구하지 않습니다.
- 앱 언어는 처음에 PC 언어를 따르며, 도구 설정에서 English·简体中文·日本語·Español·한국어·Deutsch·Français 중 고를 수 있습니다.
- ADB가 이미 있으면 재사용합니다. 없으면 앱에서 약관 동의 후 Google 공식 도구를 준비합니다. 최초 준비에는 인터넷이 필요합니다.
- 현재 개발 빌드는 공인 코드서명·공증을 마친 배포본이 아닙니다. OS 경고를 자동 해제하거나 보안 설정을 변경하지 않습니다.
- macOS의 목표 최소 버전은 12입니다. 실제 호환 범위는 네이티브 검증 후 확정합니다.
- Linux·Windows ARM 네이티브 지원은 현재 제공하지 않습니다.

릴리스마다 실행 파일의 **SHA-256 체크섬**과 검증 범위를 함께 제공합니다. 개발 시험본과 정식 지원 버전을 혼동하지 않도록 릴리스 설명을 확인하세요.

## USB로 처음 연결하기

### 1. adb-on을 엽니다

ADB가 없다는 안내가 나오면 **처음 연결 준비하기**를 누릅니다. Google SDK 약관을 확인하고 동의하면 앱이 공식 파일을 내려받아 준비합니다.

Android Studio가 이미 설치돼 있다면 보통 이 단계를 건너뜁니다. 도구를 다른 위치에 설치했다면 **도구 설정 → 이미 있는 ADB 파일 선택**에서 `adb.exe` 또는 `adb`를 선택할 수 있습니다.

### 2. 휴대폰에서 개발자 옵션을 엽니다

|휴대폰|찾아갈 메뉴|
|---|---|
|갤럭시|설정 → 휴대전화 정보 → 소프트웨어 정보 → **빌드번호** 7번 누르기|
|Pixel 등|설정 → 휴대전화 정보 → **빌드 번호** 7번 누르기|

잠금 비밀번호를 요구하면 **휴대폰에 직접** 입력하세요. 기종·Android 버전에 따라 메뉴 이름이 다를 수 있습니다.

### 3. USB 디버깅을 켭니다

휴대폰 설정의 **개발자 옵션 → USB 디버깅**을 켭니다. 이 과정은 Android 보안상 휴대폰에서 직접 해야 합니다.

### 4. 데이터 케이블로 연결하고 허용합니다

휴대폰 잠금을 풀고 **USB 디버깅을 허용하시겠습니까? → 허용**을 누릅니다. 본인 PC라면 ‘항상 허용’을 선택하면 다음 연결이 편해집니다.

adb-on이 **연결됐어요**로 바뀌면 이 PC의 개발 도구에서 휴대폰을 선택하세요.

> 충전만 가능한 케이블은 ADB 연결에 사용할 수 없습니다. 허용하지 않은 폰을 PC에서 강제로 승인하지 않습니다.

<br>

## 케이블 없이 연결하기

Android 11 이상에서 지원하는 무선 디버깅을 사용합니다.

### 1. 같은 Wi-Fi에 연결합니다

PC와 폰이 서로 통신할 수 있는 네트워크여야 합니다. 회사·학교·게스트 Wi-Fi는 기기 간 통신을 막을 수 있습니다.

### 2. 휴대폰에서 페어링 화면을 엽니다

**설정 → 개발자 옵션 → 무선 디버깅 → 페어링 코드로 기기 페어링**을 선택합니다. 이 화면을 열어 둡니다.

### 3. adb-on에서 무선 연결을 누릅니다

발견한 페어링 주소를 누르고, 휴대폰에 보이는 **숫자 6자리**를 입력해 **페어링하기**를 누릅니다. 주소가 하나만 발견되면 자동으로 채워집니다. 여러 폰이 보이면 내 폰 화면의 주소와 대조하세요.

자동 발견은 잠시 계속됩니다. 찾지 못해도 휴대폰에 표시된 **IP 주소:포트**를 직접 입력할 수 있습니다.

### 4. 연결 상태를 확인합니다

페어링은 PC를 신뢰하도록 등록하는 과정이며, 연결 완료와는 다릅니다.

연결이 안 되면 폰에서 한 화면 뒤로 가서 **무선 디버깅 첫 화면의 IP 주소 및 포트**를 adb-on의 연결 칸에 입력하고 **연결하기**를 누릅니다.

|주소|어디에 있나요?|어디에 넣나요?|
|---|---|---|
|페어링 주소|‘페어링 코드로 기기 페어링’ 팝업|① 페어링 주소 칸|
|연결 주소|무선 디버깅 첫 화면|② 연결 주소 칸|

**두 포트는 다릅니다.** 예를 들어 페어링은 `192.168.1.5:37123`, 연결은 `192.168.1.5:39511`일 수 있습니다. 예시를 복사하지 말고 폰의 값을 사용하세요.

## 다음에 다시 연결할 때

- **USB:** 이전에 신뢰한 PC라면 케이블을 꽂고 상태를 확인합니다. 승인이 다시 필요하면 폰에서 허용하세요.
- **무선:** 같은 네트워크에서 무선 디버깅이 켜져 있고 ADB가 기기를 발견하면 다시 연결됩니다. 자동 연결이 안 되면 폰의 **현재 연결 주소**를 사용하세요.
- **재부팅·Wi-Fi 변경 후:** 무선 디버깅이 꺼지거나 IP·포트가 바뀔 수 있습니다. adb-on은 낡은 주소를 저장해 계속 시도하지 않습니다.
- **앱 종료:** 창을 닫으면 adb-on은 종료합니다. 다른 개발 도구가 쓰는 ADB 서버와 연결은 유지합니다. 숨은 adb-on 상주 서비스는 없습니다.
- **무선 연결 해제:** 해당 기기의 해제 버튼을 누릅니다. ADB가 자동 재연결할 수 있으므로 확실히 끊어 두려면 폰에서 무선 디버깅을 끄세요.

## 막혔을 때 바로 찾기

|보이는 상황|먼저 할 일|
|---|---|
|휴대폰에서 승인 대기|폰 잠금을 풀고 USB 디버깅 허용 팝업 확인|
|USB를 꽂았는데 폰이 안 보임|데이터 케이블·다른 포트·USB 디버깅 순서로 확인|
|여전히 Windows에서 안 보임|[제조사 USB 드라이버 안내](https://developer.android.com/studio/run/oem-usb) 확인|
|무선 기기가 검색되지 않음|페어링 팝업을 열어 두거나 주소를 직접 입력|
|페어링 코드를 거부함|폰에서 새 페어링 팝업을 열고 새 코드·주소 입력|
|페어링됐지만 연결 안 됨|무선 디버깅 첫 화면의 **연결 주소**로 연결|
|회사 Wi-Fi에서 안 됨|같은 네트워크라도 통신이 차단될 수 있음. USB 연결 사용|
|다른 ADB 서버 버전 안내|사용 중인 개발 도구와 같은 ADB 파일 선택|
|개발 도구에서 폰을 못 찾음|동일 PC 환경의 기본 ADB 서버를 쓰는지 확인. WSL은 별도 환경|
|ADB 다운로드 실패|인터넷 연결 후 다시 준비하거나 기존 ADB 파일 선택|

앱 안의 **USB 연결 안내**에서도 같은 안내를 한 단계씩 볼 수 있습니다. 빈 기기 목록만으로 드라이버·케이블·폰 설정 중 어느 것이 원인인지 단정하지 않습니다.

## 무엇을 자동으로 하나요?

|PC에서 처리하는 일|휴대폰에서 직접 해야 하는 일|
|---|---|
|기존 ADB 찾기·연결 상태 확인|개발자 옵션·USB/무선 디버깅 켜기|
|동의 후 공식 ADB 다운로드·파일 검증|최초 PC 신뢰 승인|
|무선 주소 발견·페어링 명령·연결 요청|페어링 화면 열기·6자리 코드 확인|
|상태에 맞는 다음 행동 안내|회사 관리 정책 등 휴대폰 권한 문제 해결|

화면 미러링·파일 관리·앱 빌드·루팅·드라이버 자동 설치는 제공하지 않습니다.

## 작고 빠르다는 기준

작은 실행 파일만으로 성능을 주장하지 않습니다. 배포 전 아래 항목을 측정합니다.

- 실행부터 창이 표시되기까지의 시간.
- 유휴 CPU와 메모리. 기존 공유 ADB 서버는 별도로 구분합니다.
- 실행 파일과 최초 다운로드 용량.
- 폰 연결·분리 시 상태 갱신과 조작 중 화면 응답.

GUI는 **Rust + Slint**로 구성하고 시스템 WebView를 띄우지 않습니다. 상태 변화는 ADB의 알림을 사용하며, 무선 발견 조회는 사용자가 무선 연결을 열었을 때 제한된 시간만 수행합니다.

Windows 개발 빌드 실측(연결된 폰 없음, 2026-09-11):

|항목|결과|
|---|---|
|실행 파일|약 12.0MiB|
|유휴 메모리|작업 집합 약 126MiB, 프라이빗 약 59MiB (GPU 그리기. 작업 집합 대부분은 그래픽 드라이버 메모리)|
|세 번 재실행한 창 표시|0.47~0.57초|
|공유 ADB 서버|별도 약 4.7MiB, 기존 프로세스 유지|

각 실행에서 30초 유휴 동안 CPU 시간 0.13~0.36초를 썼습니다(한 코어의 약 0.4~1.2%). 이 빌드부터 창을 GPU로 그립니다. 자주 묻는 질문의 소프트웨어 그리기 대체는 약 30MiB를 쓰지만 스크롤이 덜 부드럽습니다. 앞선 첫 빌드의 최초 실행은 1.43초였으며, 콜드 부팅이나 다른 PC 성능을 보장하지 않습니다. 기기 연결 중 부하와 macOS 성능은 아직 검증하지 않았습니다.

## 내 PC에 무엇이 남나요?

- ADB 파일 위치 설정(`settings.json`)과, 앱에서 준비를 선택했다면 공식 ADB 복사본. 둘 다 아래 폴더에만 저장됩니다.
  - Windows: `%LOCALAPPDATA%\tinygem\adb-on\data\`
  - macOS: `~/Library/Application Support/ai.tinygem.adb-on/`
- ADB 자체가 관리하는 PC 인증키와 서버. 기존 키를 adb-on이 삭제·교체하지 않습니다.

페어링 코드는 설정·사용 로그에 저장하지 않습니다. 원격 저장 서버는 없습니다. 자동 준비 때 Google 다운로드 서버에 접속하고, 안내 링크는 기본 브라우저에서 열립니다.

앱을 그만 쓰려면 **도구 설정 → adb-on 데이터 삭제**를 누른 뒤 창을 닫고 실행 파일을 지우면 됩니다. 실행 파일을 먼저 지웠다면 위 폴더를 직접 지우면 됩니다. 여기서 준비한 ADB가 서버로 실행 중이면 삭제할 때 함께 종료되며, 다른 도구의 ADB와 ADB 인증키는 그대로 둡니다. 실행 파일을 지우는 것만으로는 이 폴더가 자동으로 지워지지 않습니다.

<br>

## 자주 묻는 질문

### 설치가 필요한가요?

아니요. `adb-on.exe` 하나를 원하는 폴더에 두고 실행하면 됩니다. 설정과 준비한 ADB는 위의 사용자 데이터 폴더에 저장되며, 도구 설정에서 지울 수 있습니다.

### 오픈소스인가요?

네. 소스 코드는 MIT 라이선스로 공개합니다. 제삼자 구성요소는 각각의 라이선스를 따릅니다.

### ADB를 몰라도 되나요?

기본 연결에는 명령어가 필요 없습니다. 휴대폰에서 해야 하는 승인과 설정은 화면에 안내합니다.

### Android Studio 없이 앱을 개발할 수 있나요?

adb-on은 연결 도구입니다. 앱을 빌드하는 데 필요한 SDK·빌드 도구를 대신하지 않습니다.

### Windows에서 연결하면 WSL에서도 되나요?

자동으로 전달되지 않습니다. Windows와 WSL은 별도 개발 환경일 수 있습니다.

### macOS에서는 Intel과 Apple Silicon 모두 지원하나요?

두 아키텍처용 빌드 경로는 준비했지만 macOS 빌드는 아직 공개하지 않았고 실제 Mac에서 검증하지도 않았습니다. 공개되더라도 Apple Developer ID 서명이 없어 처음 실행 때 한 번 마우스 오른쪽 클릭 → 열기가 필요합니다.

### 폰에 별도 앱을 설치하나요?

adb-on의 연결을 위해 폰에 별도 앱을 설치하지 않습니다. Android의 디버깅 기능을 사용합니다.

## 면책 조항

adb-on은 MIT 라이선스로 공개된 오픈소스 소프트웨어입니다. 법적 조건은 [LICENSE.txt](LICENSE.txt)의 라이선스 원문이 우선하며, 아래는 그 내용을 쉬운 말로 정리한 것입니다.

- **보증 없음.** 이 소프트웨어는 어떠한 명시적·묵시적 보증 없이 "있는 그대로" 제공됩니다. 특정 목적에 맞는다거나 오류 없이 동작한다는 보장을 하지 않습니다.
- **책임 없음.** 개발자와 기여자는 이 소프트웨어의 사용 또는 사용 불능으로 생기는 어떤 손해에 대해서도 책임지지 않습니다. 데이터 손실, 기기 오작동, 연결 실패, 업무 중단, 그 밖의 직접·간접 손해를 포함합니다. 사용 여부와 방법은 전적으로 사용자의 판단과 책임입니다.
- **개발자 옵션의 위험은 사용자가 관리합니다.** 개발자 옵션과 USB·무선 디버깅은 Android가 제공하는 기능이며, 켜 두면 연결된 PC가 휴대폰을 제어할 수 있습니다. 신뢰하지 않는 PC나 네트워크에서 켜지 말고, 사용이 끝나면 끄는 것을 권합니다. adb-on은 이 설정을 대신 관리하지 않습니다.
- **제삼자 도구는 각자의 약관을 따릅니다.** ADB는 Google의 Android SDK Platform-Tools이며 Google의 약관에 따라 제공됩니다. adb-on은 사용자를 대신해 약관을 수락하지 않습니다. 그 밖의 구성요소는 [제삼자 고지](THIRD-PARTY-NOTICES.md)의 라이선스를 따릅니다.
- **Google과 무관합니다.** adb-on은 Google 또는 Android와 제휴·후원·승인 관계가 없습니다. Android는 Google LLC의 상표입니다.
- **지원을 약속하지 않습니다.** 기능은 예고 없이 바뀌거나 배포가 중단될 수 있으며, 업데이트·문제 해결·호환성 유지를 약속하지 않습니다.
- **법이 허용하는 범위에서 적용됩니다.** 관련 법이 배제를 허용하지 않는 책임에는 위 제한이 적용되지 않습니다.

### 화면이 깨지거나 원격 데스크톱에서 스크롤이 끊겨요

adb-on은 기본으로 GPU로 그리고, 그래픽 드라이버가 OpenGL을 제공하지 못하면 스스로 소프트웨어 그리기로 바꿉니다. 그래도 창이 이상하게 보이거나 원격 데스크톱·가상 머신에서 느리면 소프트웨어 그리기를 강제해 실행하세요:

```
cmd /c "set SLINT_BACKEND=winit-software && adb-on.exe"
```

adb-on.exe가 있는 폴더에서 실행합니다. 디스크에 남기는 것은 없습니다. macOS에서는 터미널에서 같은 환경 변수를 설정한 뒤 앱을 실행합니다.
